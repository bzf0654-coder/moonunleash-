# 开发历程与技术取舍（持续更新）

这是可追溯的开发说明，不把 AI 输出写成申请人已经掌握的经历，也不补造历史提交。

## 1. 从“做一个开关库”收敛为兼容现有平台

自定义开关引擎容易演示，却会迫使使用者维护另一份规则与后台。因此选择直接消费 Unleash Client API，复用其生态；MoonBit 侧负责原生评估，而不是调用 Node/Go SDK 转发结果。不声称这是生态首个实现，也不将需求推断冒充已有用户采纳。

## 2. 先冻结测试，不反向修改预期

上游 client-specification 固定 revision `9ef6efa01feabeb699857192ad8106fd7d990235`，保留全部 22 组资料与原始许可，生成前验证 24 个文件哈希。初始确定的 11 组必过用例不因实现失败而移出范围。

第一次运行时，suite 12 因全局变体尚未支持而失败。处理方式是补全全局变体，并追加 suite 08 及所选组的 variantTests，而非删除原用例。当时 12 组实际通过 93 条；另外 201 条保留为 NotRun。

## 3. 跨语言语义比接口包装困难

- MurmurHash3 必须按 UTF-8 字节处理，并使用明确的 UInt32 溢出语义；策略桶和变体桶使用不同 seed。
- unknown flag、explicit disabled、没有匹配策略是不同结果，fallback 不能覆盖一个已知关闭的开关。
- feature_enabled 与 variant.enabled 是两个概念：功能可能开启但没有可用变体。
- 私有快照和 Context 不向调用方暴露可变 Map，避免安装后被外部修改。
- 遇到不支持的策略或运算符，拒绝整份新快照。这比“假装理解”更可观察，但也可能影响同一响应内其他开关的更新，因此必须公开说明，而不能声称与全部官方 SDK 一致。

## 4. 把网络故障做成显式状态机

[纯状态机](<../store.mbt>)不执行 I/O，由适配器提供时间。验证通过后才发布新快照与代次；304 只确认已有状态的新鲜度，不新增代次；坏 JSON、503 和超时不清空最近有效快照。批量评估捕获同一快照与代次。

[在线适配](<../online/client.mbt>)通过可替换 Transport 边界测试故障，默认使用 MoonBit HTTP 库，包含响应读取大小限制、不跟随重定向、超时与退避。with_client 将轮询任务和连接放在结构化异步作用域内，回调退出或 close 时取消受管理任务。

核对标准库发现 core/async.now 是 epoch 毫秒，并非单调时钟。因此没有把它包装成不存在的单调保证；检测回拨后清除 ETag 并停止旧快照判定，直到新的有效全量响应重建新鲜度。手动 refresh 的任务取消仍由调用方作用域负责。

## 5. 分清四种证据

1. **单元/回归测试：**测试状态边界和故障语义，不等于完整官方规范覆盖。
2. **逐条官方用例：**MoonBit 程序输出 expected/actual，Node 只校验哈希、执行进程和核对清单，不代替评估。
3. **真实 HTTP 模拟服务：**验证实际传输路径、ETag 和响应限额，不是真实 Unleash 实例。
4. **真实平台与服务器：**native、真实 Unleash 和云端 CI 没有结果时保持“待验证”，不从其他后端推断。

逐用例报告首次在 JS 上被 provenance 校验拒绝，因为 JS 与 wasm 的 argv 布局不同。随后改用编译期 target 生成后端标签，避免调用者仅改参数就伪标执行后端；三个已验证后端现在分别生成自己的报告。

## 6. AI 的实际作用与参赛者责任

本原型由 AI 辅助查询文档、组织架构、实现 MoonBit、执行测试与整理材料；没有使用子代理独立审查或额外审批流程。判断依据是工具实际输出、源码与测试，不是 AI 的完成声明。

参赛者仍应能亲自解释：为什么 seed 不同、未知字段如何处理、坏配置为何不能发布、304 为何不改代次、默认陈旧策略的风险、哪些调用会产生随机结果，以及如何复现和扩展测试。该文档不是个人背景证明或独立完成声明。

## 7. 差分没有只报告一致结果

固定 Node SDK 6.12.2 后，93 条原官方用例及 4608 条预先生成的 ASCII 共同样本一致；Unicode 诊断 48 条中却有 20 条不一致。该 profile 在执行前就按源码发现的字符串编码风险单列，并非失败后移除必过样本。

通过保持输入与 MoonBit 不变、仅临时桥接 Node primitive 的 UTF-8 输入，诊断 48 条全部对齐，定位到编码路径差异；这不是原始 Node SDK 通过兼容的证据。实现没有为变绿而改变既定 UTF-8 策略，而是加十个字节向量回归，并在项目说明首页和申报稿明确记录迁移限制。详见[完整差分结果](<DIFFERENTIAL_RESULTS.md>)。

## 8. 评估内核一致不等于在线封装契约完整

进一步核对固定 Node SDK 的实际封装，发现在线适配未补 appName/environment 默认上下文。补齐后，单项、批量、变体入口统一应用“默认值先、显式字段后”，而纯快照仍不隐式读取配置。新增 wasm 在线回归验证实际接线，另以 Node 实际 prototype 方法做 108 条针对性比较，全部一致；构造、网络、metrics 生命周期不属于这项比较。范围见[默认上下文契约](<CONTEXT_DEFAULTS.md>)。

## 9. 把策略级变体从计划落实为原生代码

2026-11-18 将首个启用策略随单次评估结果传入变体选择，避免随机策略重复求值；实现策略 groupId、stickiness、权重、override 与旧全局回退。第 16 组全部 11 条纳入必跑，三个本地运行后端推进到 104 Pass / 190 NotRun，原始 fixture 未改。

新增差分 v1 首先撞到 Node 核心在 default 策略省略 parameters 时的异常。保留原输入与首败，明确建立 v2，为默认策略补显式空参数对象，不筛选上下文、权重或预期；v2 的 11 条官方与 1536 条矩阵全部一致。旧差分仍保留 20 条 Unicode 差异。原始 SDK 的 Bricks Software AS 版权、完整许可与各改编源文件说明也同步补齐。参见 [M1 契约与结果](<STRATEGY_VARIANTS.md>)；在该历史阶段，真实服务器互通仍未完成。

## 10. 完整规范与真服务是两个独立门

2026-11-20 补齐原生约束、分组、依赖和公共原子 delta，所有原始 22 组 / 294 条在四后端执行通过，24 项文件哈希和原始预期未改。Unicode 不靠改成 Node 行为消除红字：冻结双独立 UTF-8 字节参考的 144 个完整哈希与 112 个 API 预期，保留原 20 差异及其编码原因、固定规范未定编码的边界。

真实 v7.4.0 依次暴露 Admin 路径、PostgreSQL 临时启动阶段、服务端变体必须存在 variable 项，以及容器恢复门的失败。分别保留首败；恢复候选显式固定数值端口并校验重启前后 origin，随后双目标通过，但不据此倒推旧失败原因已证实。更新 rollout 使用保留变体的 PATCH，而非会清空省略 variants 的 PUT。额外创建真正的 50/50 control/treatment 策略，以 SDK 收到的实际响应验证申请书全部七个正负例，而非仅凭蓝/金单一变体通过便宣称 A/B 示例已验收。

最终实现源码 `1f5cc6378948d1ac04655c64871e24d6bfbab665` 的[四后端完整 SDK CI](https://github.com/bzf0654-coder/moonunleash-/actions/runs/44690815957)与[双后端真服务 CI](https://github.com/bzf0654-coder/moonunleash-/actions/runs/44690815719)同 SHA 全通过。真服务还独立校验五个父开关阶段 ETag、同一客户端中断恢复、两次 metrics 接收和数据库精确计数；不让新增示例更新稀释原有验收门。公开摘要、哈希和产物元数据可核验，未把未下载的认证归档说成本地已审读。技术通过不等于 Mooncakes 发布、生产认证或正式报名成功。
