## 1. 从“做一个开关库”收敛为兼容现有平台

自定义开关引擎容易演示，却会迫使使用者维护另一份规则与后台。因此选择直接消费 Unleash Client API，复用其生态；MoonBit 侧负责原生评估，而不是调用 Node/Go SDK 转发结果。不声称这是生态首个实现，也不将需求推断冒充已有用户采纳。

## 3. 跨语言语义比接口包装困难

- MurmurHash3 必须按 UTF-8 字节处理，并使用明确的 UInt32 溢出语义；策略桶和变体桶使用不同 seed。
- unknown flag、explicit disabled、没有匹配策略是不同结果，fallback 不能覆盖一个已知关闭的开关。
- feature_enabled 与 variant.enabled 是两个概念：功能可能开启但没有可用变体。
- 私有快照和 Context 不向调用方暴露可变 Map，避免安装后被外部修改。
- 遇到不支持的策略或运算符，拒绝整份新快照。这比“假装理解”更可观察，但也可能影响同一响应内其他开关的更新，因此必须公开说明，而不能声称与全部官方 SDK 一致。

## 4. 把网络故障做成显式状态机

[纯状态机](<../store.mbt>)不执行 I/O，由适配器提供时间。验证通过后才发布新快照与代次；304 只确认已有状态的新鲜度，不新增代次；坏 JSON、503 和超时不清空最近有效快照。批量评估捕获同一快照与代次。

[在线适配](<../online/client.mbt>)通过可替换 Transport 边界测试故障，默认使用 MoonBit HTTP 库，包含响应读取大小限制、不跟随重定向、超时与退避。with_client 将轮询任务和连接放在结构化异步作用域内，回调退出或 close 时取消受管理任务。

核对标准库发现 core/async.now 是 epoch 毫秒，并非单调时钟。因此没有把它包装成不存在的单调保证；检测回拨后清除 ETag 并停止旧快照判定，直到新的有效全量响应重建新鲜度。手动 refresh 的任务取消仍由调用方作用域负责。

## 5. 分清四种证据

1. **单元/回归测试：**测试状态边界和故障语义，不等于完整官方规范覆盖。
2. **逐条官方用例：**MoonBit 程序输出 expected/actual，Node 只校验哈希、执行进程和核对清单，不代替评估。
3. **真实 HTTP 模拟服务：**验证实际传输路径、ETag 和响应限额，不是真实 Unleash 实例。
4. **真实平台与服务器：**native、真实 Unleash 和云端 CI 没有结果时保持“待验证”，不从其他后端推断。

逐用例报告首次在 JS 上被 provenance 校验拒绝，因为 JS 与 wasm 的 argv 布局不同。随后改用编译期 target 生成后端标签，避免调用者仅改参数就伪标执行后端；三个已验证后端现在分别生成自己的报告。

## 6. AI 的实际作用与参赛者责任

本原型由 AI 辅助查询文档、组织架构、实现 MoonBit、执行测试与整理材料；没有使用子代理独立审查或额外审批流程。判断依据是工具实际输出、源码与测试，不是 AI 的完成声明。

参赛者仍应能亲自解释：为什么 seed 不同、未知字段如何处理、坏配置为何不能发布、304 为何不改代次、默认陈旧策略的风险、哪些调用会产生随机结果，以及如何复现和扩展测试。该文档不是个人背景证明或独立完成声明。
